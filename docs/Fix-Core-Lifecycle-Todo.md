## 2. 修复项

### [x] FIX-01：统一脚本调用与结果检查

**问题**

- Kafka 启停通过 `run_script` 只启动子进程，不等待退出，不检查退出码。
- 脚本内部失败时，上层仍可能返回成功。
- Hadoop 已等待并检查 `run_daemon`，两个组件行为不一致。

**改造范围**

- [x] 在 `platform::process` 或 `component::exec` 提供统一的“执行并等待结果”接口。
- [x] Kafka start/stop 使用等待接口并检查退出状态。
- [x] 脚本失败时返回 stderr/stdout 摘要，日志与 GUI 都能看到原因。
- [x] 为长时间命令增加合理超时和超时后的进程清理策略。
- [x] 区分“命令执行成功”与“组件已经就绪”，就绪仍由独立状态检查判断。

**验收标准**

- [x] Kafka 脚本返回非零退出码时，Tauri 命令返回失败。
- [x] 不存在的配置或不可用 JDK 不再产生“启动成功”。
- [x] stop 失败不会删除运行记录或误导用户认为已经停止。

**回归测试**

- [x] 成功脚本返回成功。
- [x] 非零退出脚本返回包含 stderr 的错误。
- [x] 超时脚本返回超时错误且不会遗留受管子进程。
- [x] Hadoop 现有 `run_daemon` 行为不回退。

完成时间：2026-09-14。

### [x] FIX-02：配置批量提交与失败回滚

**问题**

- 配置页逐字段调用 `set_config_field`。
- 中间字段失败时，前面字段已落盘，后续字段和重启均不会执行。

**改造范围**

- [x] 增加后端 `save_config_fields` 批量命令。
- [x] 先校验全部字段，再开始写文件。
- [x] 对涉及的配置文件创建临时备份或写前快照。
- [x] 任一文件写入失败时恢复全部受管文件。
- [x] 前端由多次 invoke 改为一次 invoke。
- [x] 运行中组件的重启失败应与“保存失败”分开报告。

**验收标准**

- [x] 所有字段校验通过后才产生配置变更。
- [x] 任一步失败后，所有目标文件恢复到提交前状态。
- [x] 成功后文件内容与逐字段提交结果语义一致。
- [x] 部分失败不会导致组件静默使用半套配置重启。

**回归测试**

- [x] 成功批量提交多个字段。
- [x] 第二个字段失败时第一个字段也不落盘。
- [x] 多文件写入中途失败时全部文件回滚。
- [x] 回滚失败必须返回高优先级错误并记录日志。

完成时间：2026-09-14。

### [x] FIX-03：安装包完整性校验与网络超时

**问题**

- 缓存文件只要存在就被复用，没有 SHA256 校验。
- 下载客户端没有连接或总超时。
- 已有 `sha256_of / verify_sha256`，但下载链路未使用。

**改造范围**

- [x] manifest 为每个源版本声明完整 URL 和 `sha256`。
- [x] 下载过程中流式计算 SHA256，校验通过后再原子移动到缓存路径。
- [x] 复用缓存前重新校验；无效缓存自动删除并重新下载。
- [x] HTTP 客户端配置连接超时和总下载超时。
- [x] 错误信息区分网络请求失败、HTTP 错误和哈希不符。

**验收标准**

- [x] 损坏缓存不会被解压。
- [x] 哈希错误不会进入配置阶段。
- [x] 网络停滞时下载可以在连接超时或总下载超时后失败。

**回归测试**

- [x] 正确哈希通过。
- [x] 错误哈希被拒绝并清理缓存。
- [x] 缓存 SHA256 不一致时不视为已下载。
- [x] `.part` 文件不会被当作有效缓存。

完成时间：2026-09-14。

### [x] FIX-04：系统命令边界与 CSP 收紧

**问题**

- `open_log_file` 接受任意路径并调用系统 `open`。
- Tauri `csp` 当前为 `null`。

**改造范围**

- [x] `open_log_file` 只允许当前组件的真实日志文件。
- [x] 同时校验组件归属、扩展名、路径规范化和符号链接边界。
- [x] 校验 app 日志日期格式，只接受 `YYYY-MM-DD`。
- [x] 为 Tauri 配置最小可用的生产 CSP 和开发 CSP。
- [x] opener capability 只允许本地 WebUI URL 与 `~/.solostack` 路径。

**验收标准**

- [x] 任意路径无法通过 `open_log_file` 打开。
- [x] 不属于当前组件的日志路径被拒绝。
- [x] 正常日志查看、Finder 打开和 WebUI 跳转保留了最小权限。

**回归测试**

- [x] `..`、跨组件路径、错误扩展名和符号链接逃逸被拒绝。
- [x] 合法组件日志和 app 日志通过。
- [x] 非 `YYYY-MM-DD` 日期被拒绝。

完成时间：2026-09-14。

### [x] FIX-05：运行状态增加进程身份验证

**问题**

- 当前状态由端口是否开放推导。
- 其他进程占用相同端口时会误报 Running。

**改造范围**

- [x] 为每个组件声明 `ServiceKey`、进程命令行特征和预期监听端口。
- [x] 扫描本机进程并验证命令属于当前 `component + version` 实例。
- [x] 使用 `lsof` 验证预期端口由已匹配进程监听。
- [x] 端口只作为进程身份的补充信号，不再单独决定 Running。
- [x] 状态结果区分运行、启动中、停止、身份冲突和查询错误。
- [x] 进程身份不构成新的配置事实源，端口仍从官方配置读取。

**验收标准**

- [x] 外部进程占用目标端口时不会显示 Running。
- [x] 组件运行但端口尚未就绪时显示 Starting/Partial。
- [x] 进程异常退出后状态能自动恢复为 Stopped。

**回归测试**

- [x] 占用端口的假进程会被识别为身份冲突。
- [x] 合法进程命令行和实例路径能够匹配。
- [x] PID 复用后的其他进程无法通过命令行身份匹配。

完成时间：2026-09-14。

### [x] FIX-08：生命周期 E2E 与发布验证

**问题**

- 当前 CI 主要覆盖单元测试。
- Kafka 已完成人工真实安装和启停验证，但还没有自动回归测试。
- Hadoop/Kafka 的生命周期仍缺少可重复的 CI smoke test。

**改造范围**

- [x] 将首启初始化从 `Runtime::start` 拆为统一的 `Runtime::init`，由 `service::start` 在启动前调用。
- [x] Hadoop init：检查 `dfs.namenode.name.dir/current/VERSION`，必要时执行 `hdfs namenode -format -force`。
- [x] Kafka init：检查 `log.dirs/meta.properties`，必要时执行 `random-uuid` 和 `kafka-storage.sh format --standalone`。
- [x] 增加 Hadoop 真实安装、NameNode format、启动、状态、停止、配置修改、二次启动、卸载 smoke test。
- [x] 增加 Kafka 真实安装、KRaft format、启动、状态、停止、配置修改、二次启动、卸载 smoke test。
- [x] 验证配置修改后重启生效。
- [x] 发布前执行 Tauri debug/release 构建；debug 构建已在 release workflow 固化。

**执行方式**

- 本地：`cargo test -p solostack-core --test lifecycle_smoke -- --ignored --nocapture --test-threads=1`
- CI：手动运行 `lifecycle-smoke` workflow，或由 tag/手动 release 流程自动调用。
- smoke test 直接调用核心生命周期 API，不需要点击 GUI；使用临时 `HOME`，不会修改日常 `~/.solostack`。
- 可用 `SOLOSTACK_SMOKE_COMPONENTS=hadoop` 或 `SOLOSTACK_SMOKE_COMPONENTS=kafka` 单独复测一个组件。

**验收标准**

- [x] 两个组件都能在干净 `HOME` 下完成完整生命周期。
- [x] 两个组件首次启动都执行 init 并产生各自官方幂等产物。
- [x] 第二次启动都跳过 init，Hadoop namespace ID 和 Kafka cluster ID 保持不变。
- [x] init 失败时不会启动任何常驻进程。
- [x] 测试结束后没有残留进程、临时目录或半安装实例。
- [x] Hadoop/Kafka 的人工验证结论均由自动化 smoke test 固化。
