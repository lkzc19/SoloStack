## 1. 改造前状态

- app 操作日志主要来自代码中的 `app_log::append`。
- 当前只有 `INFO / WARN / ERROR` 三个字符串常量，没有结构化级别枚举。
- 没有统一的组件、版本、操作、`trace_id`、耗时和退出码字段。
- `platform::process` 已经捕获外部脚本的 stdout/stderr，但成功输出通常被调用方丢弃。
- 脚本失败时的输出可能进入前端错误消息，但不一定持久化到 app 日志。
- 组件自身写入 `var/log/<组件>/<版本>/` 的运行日志可以被日志页面列出。
- app 操作日志和组件运行日志目前没有统一的查看、筛选和关联方式。
- 多处 `let _ = app_log::append(...)` 会静默忽略写日志失败。

### 1.1 当前实现

- 已用 `LogLevel`、`LogRecord`、`LogContext` 建立最小日志模型。
- 日志持久化为 JSON Lines，GUI 读取结构化记录并格式化成可读列表。
- 生命周期操作具有 `trace_id`，外部脚本日志自动继承环境和 trace 上下文。
- 脚本 stdout/stderr 边读边上报，长行按 4 KB 切块，单次捕获输出限制为 1 MB。
- 已实现日志参数、环境变量和常见 Token/Password 字段脱敏。
- 已按天轮转；默认保留 7 天、总容量上限 1024 MB，可在设置页修改。
- GUI 支持日期、级别、环境、`trace_id`、文本筛选、自动刷新、诊断复制和日志目录打开。
- 日志记录、任务上下文和日志查询已包含 `environment_id`。

## 3. 建议日志模型

每条日志只保存：

```text
timestamp
trace_id
level
environment_id
message
```

示例：

```json
{"timestamp":"2026-09-18T14:30:01.123+08:00","trace_id":"V1StGXR8","level":"info","environment_id":"B2xQ7mNp","message":"启动组件 Kafka 4.3.1"}
{"timestamp":"2026-09-18T14:30:01.128+08:00","trace_id":"V1StGXR8","level":"info","environment_id":"B2xQ7mNp","message":"[KafkaServer id=1] started"}
{"timestamp":"2026-09-18T14:30:02.241+08:00","trace_id":"V1StGXR8","level":"warn","environment_id":"B2xQ7mNp","message":"[KafkaServer] WARN ..."}
{"timestamp":"2026-09-18T14:30:03.892+08:00","trace_id":"V1StGXR8","level":"info","environment_id":"B2xQ7mNp","message":"Kafka 启动完成，耗时 2.8 秒"}
```

已决定：

- [x] 持久化格式使用 JSON Lines。
- [x] GUI 读取结构后自行格式化，不额外维护一份文本日志。
- [x] 只保存时间、`trace_id`、级别、环境和消息五个字段。
- [x] `v0.2.0` 只读取当前 `trace_id` 格式，不再兼容旧 `task_id` 字段。
- [x] `trace_id` 使用 8 位 NanoID，不包含组件、版本或操作等业务含义。

## 4. 日志分级

建议定义：

```rust
enum LogLevel {
    Error,
    Warn,
    Info,
    Debug,
    Trace,
}
```

使用建议：

- `ERROR`：操作失败、脚本非零退出、回滚失败、无法恢复的异常。
- `WARN`：可恢复异常、超时后清理、停止失败、校验失败。
- `INFO`：用户可感知的操作开始/结束、安装、启停、配置保存、环境切换。
- `DEBUG`：脚本参数、工作目录、环境变量白名单、状态轮询结果。
- `TRACE`：逐块进程输出、底层重试和高频诊断；默认关闭。

默认策略：

- [x] 发布版本默认 `INFO`。
- [x] 开发模式默认 `DEBUG`。
- [x] 设置页允许切换日志级别。
- [x] 高频状态轮询不能写入 INFO。

## 5. 外部脚本日志

所有通过 `component::exec` 和 `platform::process` 执行的脚本必须自动记录。

### 执行前

- [x] 默认只记录脚本执行消息和 `trace_id`。
- [x] 脚本路径、参数、超时等细节仅在 DEBUG 写入消息。
- [x] 对密码、Token、Cookie 和认证参数脱敏。

### 执行中

- [x] stdout 原始内容写为 INFO 消息。
- [x] stderr 原始内容写为 WARN 消息。
- [x] 没有换行的长输出也要按大小切块，避免无限缓冲。
- [x] 取消安装时记录来源和阶段；安装不执行组件脚本，脚本终止状态为 `not_applicable`。

### 执行后

- [x] 退出码、duration 和 timeout 合并写进可读消息。
- [x] 取消统一记录为单条可读消息，不再同时写取消和失败两条记录。
- [x] 失败时记录 stdout/stderr 的末尾摘要。
- [x] stdout 默认写 INFO，stderr 默认写 WARN。
- [x] 出错时消息至少提升到 ERROR。

## 6. 日志分层

### app 操作日志

```text
~/.solostack/app/log/
```

职责：

- SoloStack 自身操作。
- 生命周期编排。
- 外部脚本命令与输出。
- 配置事务和环境切换。

### 组件运行日志

```text
~/.solostack/var/log/<component>/<version>/
```

职责：

- Hadoop/Kafka 自己输出的运行日志。
- 组件进程日志、GC 日志和访问日志。

规则：

- [x] 不把组件长时间运行日志复制进 app 操作日志。
- [x] app 日志记录环境、`trace_id` 和可读消息。
- [x] 日志页面可以关联显示 app 操作日志与组件运行日志。
