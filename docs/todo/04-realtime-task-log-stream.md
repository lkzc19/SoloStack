# 04 SoloStack 实时任务日志流 TODO

> 状态：下一版本实施。
> 前置：`02-structured-logging.md` 的结构化存储、任务上下文和脚本输出桥接。
> 目标：参考 Flink Web UI 的任务日志体验，在 SoloStack 中持续跟随日志，而不是每次重新读取完整文件。

---

## 1. 目标行为

- [ ] 打开日志视图时，先回填最近 N 行。
- [ ] 回填完成后自动进入实时跟随模式。
- [ ] 持续显示应用操作、脚本 stdout/stderr 和组件运行日志。
- [ ] 用户可以暂停和恢复实时更新。
- [ ] 用户可以停止自动滚动，继续保留已经显示的日志。
- [ ] 可以按组件、版本、操作和任务 ID 只看一组日志。
- [ ] 显示实时状态：跟随中、已暂停、当前 offset、丢弃的 UI 行数。
- [ ] 日志文件被轮转、截断或重新创建时，不中断后续跟随。
- [ ] 可以为一次任务打开独立日志视图，关联该任务产生的全部日志。

---

## 2. 建议架构

后端新增统一 `LogHub`：

```text
app_log 写入
script stdout/stderr
component var/log 文件
        ↓
      LogHub
        ↓
 有界缓冲 / 批量聚合
        ↓
 Tauri event / 本地流式接口
        ↓
 前端虚拟化日志列表
```

建议模块：

```text
crates/core/src/lifecycle/log_stream.rs
```

核心组件：

- [ ] `LogSourceSpec`：描述 app、script 或组件日志来源。
- [ ] `FileFollower`：按路径和 offset 跟随文件。
- [ ] `LogHub`：订阅、取消订阅、合并来源和广播批次。
- [ ] `LogBatch`：批量推送日志，避免逐行 IPC。
- [ ] `StreamStatus`：跟随状态、文件轮转状态、丢弃行数和错误。

---

## 3. 文件跟随规则

- [ ] 记录文件路径、文件身份、offset 和轮转代次。
- [ ] 文件增长时只读取新增字节。
- [ ] 文件被轮转后自动切换到新文件。
- [ ] 文件长度小于原 offset 时按截断处理，从文件头重新读取。
- [ ] 保留未完成行，下一次读取补齐后再输出。
- [ ] 兼容 UTF-8、非 UTF-8 和无换行长行。
- [ ] 读取速度慢时使用有界队列，不能无限占用内存。
- [ ] UI 队列满时允许丢弃实时显示，但磁盘日志不能被丢弃。

---

## 4. 任务级关联

- [ ] 复用生命周期 `task_id`，关联操作日志和脚本日志。
- [ ] 为一次操作建立 `execution` 视图。
- [ ] 组件日志通过组件、版本和操作时间窗口关联。
- [ ] 未来接入 Flink Job 时使用 Job ID 关联 JobManager/TaskManager 日志。
- [ ] 多环境模型确定后，将 `environment_id` 纳入日志流过滤维度。

---

## 5. Tauri 接口

- [ ] `start_log_stream(sources, backfill_lines)`。
- [ ] `stop_log_stream(stream_id)`。
- [ ] `pause_log_stream(stream_id)`。
- [ ] `resume_log_stream(stream_id)`。
- [ ] 事件 `log-stream://batch`：批量日志。
- [ ] 事件 `log-stream://status`：offset、轮转、丢弃和错误状态。

---

## 6. 前端日志视图

- [ ] 使用虚拟化列表，不能把全部日志放进单个 `<pre>`。
- [ ] 默认跟随最新日志。
- [ ] 用户向上滚动时暂停自动滚动。
- [ ] 滚回底部时恢复跟随。
- [ ] “暂停”只暂停前端更新，不停止后端记录。
- [ ] “清空”只清当前视图，不删除日志文件。
- [ ] 支持搜索和最小化来源筛选。
- [ ] 支持复制当前诊断视图。
- [ ] 显示“实时跟随 / 已暂停 / 已加载 N 行 / 丢弃 N 行”。

---

## 7. 非目标

- [ ] 第一阶段不引入 Elasticsearch、Loki 或其他远程日志服务。
- [ ] 第一阶段不上传用户日志。
- [ ] 第一阶段不要求浏览器远程访问；优先使用 Tauri command/event。
- [ ] 不把组件长时间运行日志全文复制进 app 日志。

---

## 8. 验收标准

- [ ] 打开日志页时能回填历史日志并自动跟随新增日志。
- [ ] 暂停后日志文件仍持续增长，恢复后能继续读取。
- [ ] Kafka/Hadoop 日志轮转后仍能继续实时显示。
- [ ] 一次任务的 app、脚本和关联组件日志可以在同一视图中查看。
- [ ] 高频日志不会导致 UI 无响应或内存无限增长。
- [ ] 关闭日志视图后，所有 follower 和订阅均被释放。

---

## 9. 实施顺序

1. `FileFollower` 和 offset/轮转测试。
2. `LogHub` 与 app/script 实时订阅。
3. Tauri stream command/event。
4. 虚拟化日志视图和跟随/暂停 UI。
5. 组件日志文件接入。
6. 任务级 `execution_id` 和多环境日志维度。
