# SoloStack 数据迁移设计

> 描述 SoloStack 如何在版本演进中迁移磁盘布局，以及当前基线版本与未来迁移步骤的约定。
> 活文档，随 `crates/core/src/app/migration/` 同步维护。

## 1. 定位

- **目标**：磁盘布局变化时，已有数据能够按版本安全迁移。
- **当前状态**：`v0.2.0` 是最低支持版本，数据布局基线为 `v1`，暂不包含迁移步骤。
- **非目标**：本文不使用 app release 版本作为迁移键，也不支持 `v0.1.x` 数据。

## 2. 版本模型

迁移键是**数据布局版本**，不是 app 版本。一个 app 版本可以包含零个或多个布局迁移。

| 布局版本 | 含义 |
|---|---|
| `1` | `v0.2.0` 建立的基线：`app/`、`cache/`、`environments/`，组件按环境隔离 |

`v0.1.x` 的旧全局布局不在支持范围内，不提供迁移路径。

## 3. 标记与门控

标记文件：

```text
~/.solostack/.migration-version
```

读取规则：

- 标记存在且内容有效：使用文件中的布局版本。
- 标记缺失或内容无效：按基线版本 `1` 处理，并重新写入标记。
- 标记版本高于程序支持版本：拒绝继续启动，提示用户升级程序。

当前入口：

```rust
solostack_core::app::migration::run()
```

`run()` 在应用启动阶段执行。低于当前最高版本时按 `STEPS` 依次运行迁移，全部成功后再写入最新版本；失败时保留原版本，允许下次启动重试。

## 4. 未来迁移步骤

当前步骤表为空：

```rust
const STEPS: &[MigrationStep] = &[];
```

新增布局迁移时：

1. 将 `CURRENT_LAYOUT_VERSION` 增加 `1`。
2. 在 `STEPS` 末尾追加 `(N, migrate_to_vN)`。
3. 实现只处理 `N-1 → N` 的增量迁移。
4. 补充迁移测试，并更新本文的版本表。

迁移步骤必须：

- 幂等，可以安全重试。
- 先写入临时位置，成功后整体提交。
- 中途失败时回滚，不留下半迁移状态。
- 遇到目标冲突或无法判断的数据时停止并报错，不覆盖、不静默删除。

## 5. 模块结构

```text
crates/core/src/app/migration.rs       门控入口、当前版本、迁移步骤表
crates/core/src/app/migration/version.rs
                                      `.migration-version` 读写
```

只有新增真实迁移时才增加具体迁移模块，避免为不存在的兼容路径保留空抽象。

## 6. 测试

当前覆盖：

- 缺少版本标记时写入基线版本。
- 版本标记无效时重置为基线版本。
- 数据版本高于程序支持版本时拒绝启动。

未来每个迁移步骤都需要补对应的数据构造、成功迁移、重复执行和失败回滚测试。
